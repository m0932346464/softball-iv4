# 慢壘賽事紀錄系統（Firebase 版・互動版 v3）

兩個網頁共用一個 Firebase 資料庫：

| 網頁 | 給誰用 | 功能 |
|---|---|---|
| `index.html` 後台資訊中控 | 場邊紀錄員（手機／平板） | 選場次、記錄擊球落點、更新比分；多台裝置即時同步，斷網時先存在裝置上 |
| `admin.html` 管理後台 | 賽務／管理員（電腦） | 賽事設定、球隊與名單匯入、賽程與比分、球隊戰績、個人打擊排行、紀錄員權限 |

## 一、建立 Firebase 專案（約 10 分鐘）

1. 到 <https://console.firebase.google.com> 建立專案（Google Analytics 可關閉）。
2. **Authentication** → 開始使用 → 登入方式 → 啟用「電子郵件/密碼」。
3. **Firestore Database** → 建立資料庫 → 選「正式版模式」，地區建議 `asia-east1`（台灣）。
4. 專案設定（齒輪）→ 一般 → 你的應用程式 → 新增「網頁」應用程式，複製出現的 `firebaseConfig`，貼到 `public/config.js`。

## 二、上線

在這個資料夾開終端機：

```bash
npm install -g firebase-tools
firebase login
firebase use --add          # 選剛建立的專案
firebase deploy             # 同時部署安全規則與網頁
```

完成後會顯示網址，例如 `https://你的專案.web.app`（後台資訊中控）與 `https://你的專案.web.app/admin.html`（後台）。

不想用指令列也可以：把 `firestore.rules` 的內容貼到 Firestore → 規則 → 發布；網頁檔案（`public` 資料夾）放到任何靜態網站空間即可。

## 三、設定第一位管理員

1. 打開網站的 signup.html（紀錄員註冊頁，各頁登入框下方也有「前往註冊」連結），填姓名、Email、密碼完成註冊。
2. 到 Firebase 主控台 → Firestore → `users` 集合，找到你的 Email 那一筆，把 `role` 從 `pending` 改成 `admin`。
3. 重新整理，就能進入管理後台。之後其他紀錄員註冊後，在後台「帳號」分頁直接開通即可。

## 四、賽前準備（後台）

1. **賽事**：建立賽事，選球場規格（男子／混合 300 呎、女子 275 呎或自訂）。
2. **球隊名單**：新增各校球隊與組別，貼上名單匯入。每行「背號 姓名 左右打」，可從 Excel 直接複製，左右打可省略；同背號再次匯入會更新資料。
3. **賽程比分**：新增場次（日期時間、場地、輪次、客隊／主隊）。
4. **紀錄員**：把註冊的紀錄員權限改為「紀錄員」。

## 五、比賽中（後台資訊中控）

選賽事與場次 → 選攻擊方（客隊為上半局、主隊為下半局）→ 選打者、結果、擊球型態 → 點球場落點。
比分可在頂部直接加減，記錄第一球時場次會自動變成「比賽中」，結束後把狀態改為「已結束」，戰績才會計入。
「全賽事」可看該隊整個賽事所有場次的落點分佈，用來排守備。

## 資料結構

```
users/{uid}                     email, role(pending|scorer|admin)
tournaments/{tid}               name, startDate, endDate, field{L,C,B,P}
tournaments/{tid}/teams         name, group
tournaments/{tid}/players       teamId, no, name, bats(R|L|S)
tournaments/{tid}/games         gameNo, scheduledAt, field, round, awayId, homeId, awayScore, homeScore, status
tournaments/{tid}/balls         gameId, teamId, batterId, batterNo, batterName, side, inning, half,
                                result(1B|2B|3B|HR|OUT|E), type(G|L|F|P), x, y(呎，本壘為原點), zone(落點格), createdBy, createdAt
```

## 權限（firestore.rules）

- 賽事、球隊、名單、賽程比分：任何人可讀（之後可以做公開戰績頁），只有管理員可修改。
- 紀錄員：可新增、刪除落點，可更新比分、局數與比賽狀態。
- 擊球落點：只有紀錄員與管理員能讀（屬於球探資料）。

## 統計說明

個人排行以後台資訊中控的擊球落點計算，只計擊出的球（不含三振、四壞），所以「安打占比」不等於正式打擊率。若要正式打擊率，需要再加上每個打席的紀錄（含三振、四壞、犧牲打）。

## 費用

Firebase 免費的 Spark 方案每天有 5 萬次讀取、2 萬次寫入，一般校際賽事的紀錄量用不完。

## 本機測試（選用）

```bash
firebase emulators:start
```
然後開 `http://127.0.0.1:5000/?emu=1`，資料只存在本機模擬器，不會動到正式資料庫。

## 逐局比分紀錄（score.html）

電子化的「逐局比分紀錄」。選日期與場地後，依時間列出該場地所有場次，每場輸入 1–7 局（另有 8、9 延長局）得分，合計自動計算；按「比賽結束」後計入勝敗與積分。
不登入可唯讀檢視；紀錄員登入後可輸入。輸入後即時同步到所有裝置與後台「成績統計 → 預賽分組積分」。
積分：勝 3、和 1、敗 0；同分依 1.勝負關係 2.總失分少 3.總得分多 4.總局數。

## 賽前匯入順序

1. 後台「賽事」建立賽事
2. 「球隊名單」→ 選擇 CSV 並匯入：2026全國E壘_球員名單_匯入用.csv（含組別）
3. 「賽程比分」→ 選擇 CSV 並匯入場次：2026全國E壘_預賽場次_匯入用.csv（60 場）


## 使用流程

### 開打前（管理後台）
1. 賽事：名稱、舉辦期間、秩序冊連結
2. 球隊名單：匯入 2026全國E壘_球員名單_匯入用.csv（含組別）
3. 賽程比分：匯入 2026全國E壘_預賽場次_匯入用.csv
4. 歷史落點查詢：後台資訊中控選對手場次與攻擊方，範圍選「本隊・歷屆」或「打者・歷屆」

### 開打中（後台資訊中控 index.html）
1. 打擊順序：按「打擊順序／替補」，可依背號自動排 11 棒（10 人守備＋1 名 EP，EP 可排任何棒次、可用 ↑↓ 調整）、沿用上一場，或逐棒指定球員與守位；系統會檢查 11 棒、10 守位是否齊全
2. 替補：該棒按「替補」，選上場球員與起始局數，原球員保留紀錄
3. 依打序記錄：選結果後點落點（三振、四壞按「記錄」），自動換下一棒；「復原上一筆」會回到上一棒
4. 本場 vs 歷史：「本場 vs 歷史」分頁顯示目前打者本場與歷屆的打擊率、上壘率、長打率、落點
5. 當次成績：「本場成績」分頁為本場每棒的打席、打數、安打、全壘打、四壞、三振
   逐局比分在「逐局比分紀錄」(score.html)

### 開打後（管理後台「成績統計」）
- 預賽分組積分、團隊打擊、個人打擊成績（打席、打數、安打、二安、三安、全壘打、壘打數、四壞、三振、高犧、打擊率、上壘率、長打率、OPS、拉打率）
- 各項指標排行榜：打擊率、全壘打、安打、上壘率、長打率、OPS、壘打數、四壞


## 互動版 v3：打擊落點紀錄上傳與後台匯入

`sheet.html`（打擊落點紀錄）依「落點紀錄表第三版」範本的格位與代號電子化登載：

1. **記錄員登載**：填隊伍與第 1–10 棒背號，依序點落點、按結果；每半局結束按「換局 ▶」。替補、代跑、得分打點的記法見使用指南。沒有網路也能記，資料先存在平板上。
2. **上傳**：按「☁ 上傳」，用紀錄員帳號登入，選賽事、場次、本隊（先攻／後攻）後上傳。資料存到 `tournaments/{賽事}/uploads`，狀態為「待匯入」。修改後可以再上傳，後台會標示哪一份是最新的。
3. **後台匯入**：管理後台「待匯入」分頁，依背號自動對到該隊名單（對不到的可手動選），按「匯入」：
   - 取代該場該隊既有的打席紀錄（`balls`，標記 `source: "sheet"`），落點格位換算成球場座標，結果代號換成系統代號（F／G／RE → 出局、FS → 高犧、GS → 滾犧）；
   - 更新該場本隊的逐局得分、比分與打擊順序；
   - 上傳狀態改為「已匯入」。也可以「退回」並填原因。
4. **同步更新**：後台資訊中控詳細數據、逐局比分紀錄、預賽排名、後台成績統計都直接讀資料庫，匯入後自動更新。

### 自動回報逐局比分

- 打擊落點紀錄按「🔗 連結本場」，選賽事、場次與本隊（先攻／後攻）。
- 之後每局三人出局（或按「換局」）時，自動把本隊這半局得分寫到該場的「逐局比分紀錄」，比分與預賽排名看板跟著更新；改了前面局的得分也會重新回報。
- 需要網路並登入開通的紀錄員帳號；沒網路時按鈕顯示「待回報 N 局」，連線後每 30 秒自動補送。
- 比賽已標記結束時不再自動回報，請改由管理員匯入或在逐局比分紀錄重新開啟。
- 賽後仍要按「☁ 上傳」，讓管理員匯入每個打席的資料。

### 球隊／球員名單比對

- 打擊落點紀錄開啟時會讀取系統裡最新一屆賽事的球隊與球員名單（名單是公開可讀，不必登入），並存在平板上，離線也能比對。
- 「隊伍」欄輸入校名或隊名、從清單選定後，顯示「✓ 隊名・人數」；表格多一欄「姓名」，輸入背號自動帶出人名。
- 同一隊有兩位以上同背號時跳出選單挑選；名單沒有這個背號時，「姓名」欄顯示「＋新增」，可輸入姓名與性別新增。
- 新增的球員：已登入的紀錄員會直接寫入系統名單（`players`，安全規則只允許新增、不能修改或刪除）；離線時先存在平板，上傳紀錄表時一起寫入。
- 後台匯入時，紀錄表上已選好的球員優先使用；同背號有兩位以上而紀錄表沒選的，要在「待匯入」手動選。

### 部署注意

- 這一版的 `firestore.rules` 新增了 `uploads` 的權限，並允許管理員在比賽已結束時匯入更正。**部署網頁之前要先發布新的安全規則**（Firebase 主控台 → Firestore → 規則，貼上 `firestore.rules` 全文 → 發布），否則上傳會出現「沒有權限」。
- 不需要升級 Firebase 付費方案。

## 後台資訊中控（戰情統計）

打擊紀錄已改由「打擊落點紀錄」登錄、賽後上傳由管理員匯入，後台資訊中控不再提供逐打席登錄，改為戰情統計：

- 選場次與查詢球隊後，左側列出本場打序（未上場者列在後面；尚未匯入打序時依背號排列）。
- 點選球員：球場顯示該球員歷屆＋本場（或只看本場）的落點，右側顯示左中右傾向、守備建議，以及本場／歷屆／合計的打席、打數、安打、打擊率、HR、BB、K 與打席明細。
- 「詳細數據」保留打者落點一覽、紀錄表、本場成績、本場 vs 歷史、統計、明細、賽事轉播稿。

### 戰情看板（兩種模式）

- **比賽中・防守準備**：選本場對手，顯示「即將上場」5 位打者（下一棒起）、其餘打序與可能替補。打序、下一棒與本場打席由「打擊落點紀錄」連結本場後即時回報（寫在場次文件的 `live.away`／`live.home`），不必等賽後匯入；尚無即時打序時改用已匯入的打序或預測打序。
- **賽前・全隊情蒐**：依該隊最近一場的打序預測先發，其餘依近 3 場出賽次數排序，每位球員附落點小圖、左中右傾向與守備建議，可列印。
- 點任一位球員進入「單一球員」，看完整落點（點位／分格／熱區）與本場、歷屆成績。
- Firestore 規則：紀錄員更新場次時允許寫入 `live` 欄位（請重新部署 firestore.rules）。
- **查單一球員**：
  - 打擊落點紀錄目前打者旁的「🔍 查此打者」（或從打擊落點紀錄點「後台資訊中控」），會直接開啟只顯示這位打者的畫面；按「顯示全隊」回到清單。
  - 上方先「① 選學校」再「② 選球員」，選定後直接進入單一球員。
  - 單一球員畫面：左欄為球員統計（本場／歷屆／合計：出賽、打席、打數、安打、一二三安、全壘打、打點、四壞、三振、失誤上壘、野選、犧牲打、雙殺、打擊率、上壘率、長打率、OPS、三振率，以柱狀圖呈現打席結果與擊球型態），中間球場落點，右欄守備傾向與逐場紀錄。

### 賽後統計分析（在逐局比分紀錄內）

比賽標記結束後，逐局比分紀錄該場會出現「賽後統計分析 ›」，在頁面內開啟該場詳細數據，分頁依「本場（本場成績、紀錄表、明細）／歷史（本場 vs 歷史）／累計（統計、打者落點一覽）／其他（賽事轉播稿）」排列，右上角可切換先攻／後攻隊。後台資訊中控不再顯示「詳細數據」入口。

## 歷史資料維護（賽務管理後台 →「歷史資料」分頁）

- **球隊別名**：「球隊名單」選一隊，在「別名」填其他屆用過的隊名（逗號分隔）。後台資訊中控查歷屆時，隊名或別名相同就算同一隊（teams.aliases）。
- **歷史落點 CSV 匯入**：先在「賽事」新增過去那一屆並切換過去，再到「歷史資料」下載範本、照格式整理紙本後匯入。欄位：日期、場次、隊伍、對手、先後攻、局、棒次、背號、姓名、結果、落點、打點、左右打；結果與落點用紀錄表代號（高犧寫 SF 或 FS 都可）。左右打填 左／右／左右，可留空：新球員依此建立，已在名單的球員若不同會更新，預覽會先列出。匯入前會預覽並列出錯誤列；沒有的球隊、場次（狀態「已結束」、輪次「歷史匯入」）與球員自動建立。每個打席記 histKey，同一份檔案重複匯入會略過；每批有 histBatch，可整批刪除（同批自動建立且沒有其他資料的場次、球員、球隊一起刪）。
- **球員跨屆對照**：預設以「同隊（含別名）＋同姓名」把別屆打席算給本屆球員。對照表列出背號相同但姓名不同、或同名多人的情況，按「是同一人」寫入 players.hist（'屆別id/球員id'），按「不是」寫入 players.histNo 排除。
- **封存與備份**：「匯出打席 CSV」與匯入範本同格式，可再匯入；「下載完整備份」為 JSON（球隊、名單、賽程、打席、上傳）。「封存本屆」在賽事寫入 archived: true：後台鎖住編輯、逐局比分紀錄改為唯讀、打擊落點紀錄不能上傳到這一屆；firestore.rules 也擋下封存賽事底下所有新增、修改與刪除，需由管理員解除封存後才能更正。

## 比賽計時與比賽結束（打擊落點紀錄）

- 「⏱ 開賽計時」：預賽 50 分鐘（滿 45 分鐘不開新局）、複決賽／排名賽 60 分鐘（滿 55 分鐘不開新局），依場次輪次自動帶入，可改開賽時間。倒數狀態存在兩隊紀錄表上。
- 自動請紀錄員確認比賽結束：打完 7 局、第 7 局上半結束後攻領先、滿 45 分鐘後一局打完、時間到後後攻在下半局領先。也可隨時按「🏁 比賽結束」（棄權、天候等）。
- 確認後兩隊紀錄表鎖住新打席，補回報最後一個半局的比分，並把場次標記 status: 'final'、endReason（結束原因，逐局比分紀錄顯示）；firestore.rules 已允許紀錄員寫入 endReason。
- 工具列的 CSV、備份、還原、列印收在「⋯ 更多」。
- 比賽結束後自動上傳：紀錄員按「確認比賽結束」後，系統依序回報最後比分、標記場次已結束，並把兩隊紀錄表上傳到後台「待匯入」（uploads.auto = true）。沒網路或未登入時按鈕顯示「☁ 待上傳」，恢復後自動補傳；沒有連結場次的紀錄表會改為開啟上傳視窗。
- 上傳鍵平常只顯示狀態：比賽中「☁ 賽後自動上傳」、已送出「☁ 已上傳」（不可按）；只有「☁ 待上傳」「☁ 重新上傳」（橘色）或沒有連結場次時可以按。
- 連結／上傳防呆：所選場次的兩隊必須和紀錄表上的兩隊相同才能連結或上傳；先後攻依賽程自動帶入；已回報過比分的紀錄表要改連別場須再按一次確認；隊伍不在連結場次時不回報比分與即時打序。
- 「🔗 連結本場」：已連結時只開狀態與跳頁選單（改場次要點「連結錯了？重新選場次」）；選場次清單只列兩隊相符的場次，只有一場就自動選好。
- 賽後統計分析：本場成績、紀錄表、明細合併為「本場成績」一頁（紀錄表格式＋完整成績欄），可切換「依打序／依局數」。
- 各裝置版面：打擊落點紀錄在平板直放時改為上下排列（球場、結果按鈕在上，紀錄表在下），手機開啟會提示改用平板橫放（仍可選擇繼續）；本場成績在窄螢幕可左右滑並固定棒次、姓名欄；逐局比分紀錄在手機一次顯示九局與合計；後台資訊中控手機頁首精簡；預賽排名看板手機點學校可看場數、防守局數、名次依據；賽務管理後台手機分頁排成兩行。
- 公開頁面（逐局比分紀錄、預賽排名看板）的「打擊落點紀錄」連結只對已登入的紀錄員／管理員顯示；打擊落點紀錄沒登入或未開通時頂端顯示黃色提示與登入鈕（仍可離線先記）。

## 第四版（互動版 v4）新增

### 只標例外：女生、左打（紅色）
- 只標少數需要注意的資訊：女生在背號旁標紅色「女」，左打在姓名後標紅色「左」（左右開弓標「左右」）；男生、右打不標。
- 名單沒填性別的，在背號旁標灰色「?」（每個地方都標），提醒到賽務管理後台補上；下拉選單顯示「（性別未填）」。
- 打擊落點紀錄：「女」在背號格、「左」接在姓名後。後台資訊中控：顯示成「#18 女 蔡佳岑 左」；下拉選單顯示「（女・左打）」。
- 原本卡片上的「右打／左打」文字拿掉，改由紅色「左」標示。
- 共用函式在 common.js：`pLab(p)`（含標示的背號姓名）、`femTag`、`handTag`、`sexOpt(p)`。

### 歷屆範圍篩選
- 後台資訊中控上方「③ 歷屆範圍」：全部／最近 20／50／80 打席，選擇會記在這台裝置。
- 依每位打者（含跨屆對應到的同一人）由新到舊取最近 N 個打席（保送、犧牲打都算一席）。
- 只影響歷屆資料；本場資料一律全部顯示。選了非「全部」時選單會變黃色提醒。

### 待匯入：背號不在名單時直接加入
- 紀錄員在打擊落點紀錄填了名單上沒有的背號（漏登錄或臨時上場），管理員在「待匯入」對應球員時，該列會出現「名單沒有 #N，直接加入」：姓名預填紀錄表上寫的，選性別、打擊後按「＋ 加入名單並對應」，球員就加入本隊名單並自動對應，不必跳到「球隊名單」再回來。

### PWA（加入主畫面、離線開啟）

- `docs/manifest.webmanifest`：App 名稱、圖示（`docs/icons/` 內的 PNG，iPhone 用 `apple-touch-icon.png`）。
- `docs/sw.js`：離線外殼。頁面先抓網路，沒訊號時用手機上存的版本；CSS、JS、Firebase 程式庫先用快取再背景更新。Firestore 資料不經過這裡，仍由 `enablePersistence` 處理離線寫入。
- 每頁 `<head>` 都會註冊 `sw.js`。**改版後若手機沒更新，把 `sw.js` 裡的 `VERSION` 加一再推上去。**
- 紀錄員要在有網路時先打開一次，之後才能離線開啟。
